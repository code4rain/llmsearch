# llmsearch 설계 문서

날짜: 2026-08-17
상태: 승인 대기
검토 이력: 적대적 리뷰(16건) · 시니어 엔지니어 요구사항 리뷰(9건) · 베테랑 문서 구조 리뷰(7건) · LLM 활용 최적화 리뷰(4건) · PARA 문서관리 리뷰(5건) 반영 완료 (부록 A 참조)

## 1. 개요

개인용 통합 문서 검색 GUI 툴. 5개 소스(로컬 문서, Confluence, Jira, Outlook 메일, Outlook 일정)를 하나의 인덱스로 모아, 채팅형 UI에서 자연어 질문을 하면 LLM이 **답변 + 근거 원본 문서 링크**를 돌려준다.

**사용 환경**: 회사 Windows 노트북 1대, 개인 사용. 개발은 WSL2, 실행은 Windows Python 단일 프로세스. 브라우저로 `http://127.0.0.1:<port>` 접속.

**성공 기준 (P1, M1에 평가 스크립트 포함)**: 골든 질문 세트(사용자가 만든 질문 10~20개 + 기대 문서)에서 기대 문서가 검색 상위 3위 안에 드는 비율 ≥ 70%. 채팅 답변 시작까지 10초 이내(검색 <1초, Claude 첫 토큰 <3초 목표).

## 2. 하지 않을 것 (Out of Scope)

- Confluence 페이지 첨부파일 수집
- 회사 일정 시스템 연동 (추후 검토 — 커넥터 인터페이스로 확장 가능하게만 설계)
- 로컬 LLM / 로컬 임베딩 (인터페이스만 열어두고 v1은 API 전용)
- 다중 사용자, 권한 관리, 원격 접속 (127.0.0.1 고정)
- 메일 발송·일정 등록 등 쓰기 기능 (읽기 전용)
- 모바일 UI

## 4. 마일스톤

각 마일스톤은 독립적으로 유용하며, 완료 시점부터 실사용 가능하다.

- **M1 — 코어 검증**: 인덱스 층 + 검색 파이프라인 + 채팅 GUI + 커넥터 2종(`notes`, `local_docs`) + 골든 평가 스크립트. 첫날 스파이크: sqlite-vec Windows 휠 동작 확인(§10).
- **M2 — Outlook**: `outlook_mail` + `outlook_cal` 커넥터, COM 전용 워커 스레드, 콜드스타트(재개 가능 초기 인덱싱).
- **M3 — Confluence/Jira**: 인증 3단 폴백 진단, 페이지 트리 미러, Jira 이슈+댓글.

## 5. 아키텍처

```
[커넥터 층]                [인덱스 층]                [검색/GUI 층]
 local_docs  ─┐
 confluence  ─┤   →   청킹 + 임베딩 + 저장    →    FastAPI (127.0.0.1)
 jira        ─┤        index.db (SQLite:            ├ 채팅 탭 (SSE 스트리밍)
 outlook_mail─┤        FTS5 + sqlite-vec)           ├ 소스 탭 (상태·설정·수동 동기화)
 outlook_cal ─┘                                     └ 로그 탭
        ↑
 동기화 스케줄러 (앱 실행 중, 소스별 주기, 기본 30분 + 수동 버튼)
```

원칙:
- 커넥터는 서로를 모르고, 인덱서만 커넥터를 호출한다. 커넥터 실패는 소스별로 격리된다.
- 쓰기(인덱싱)는 인덱서 단일 스레드로 직렬화, SQLite는 WAL 모드 (P0 — 동시 읽기/쓰기 잠금 방지).
- Outlook COM 접근은 전용 워커 스레드 1개로 격리하고 시작 시 `pythoncom.CoInitialize()` 호출. 다른 컴포넌트는 큐로 요청 (P0 — FastAPI 스레드풀에서 COM 직접 호출 금지).
- 스케줄러는 놓친 주기를 보정하지 않는다. 매 실행이 "마지막 성공 동기화 이후 변경분"을 가져오므로 절전·Outlook 미실행 후 자연 복구된다.

## 6. 핵심 인터페이스

```python
@dataclass
class Document:
    source_type: str        # "local_docs" | "confluence" | "jira" | "outlook_mail" | "outlook_cal"
    source_id: str          # 소스 내 고유 ID (파일 경로, 페이지 ID, EntryID 등)
    title: str
    text: str               # 인덱싱 대상 본문 (DRM 문서는 메타데이터 설명문)
    url_or_path: str        # 원본 열기용 (파일 경로 / URL / outlook:EntryID)
    updated_at: datetime
    content_indexed: bool   # False = DRM 등으로 메타데이터만 인덱싱됨
    extra: dict             # 소스별 부가정보 (보낸이, 참석자, 카테고리 등)

class Connector(Protocol):
    source_type: str
    def sync(self, config: SourceConfig, state: SyncState) -> SyncResult: ...
    # SyncResult = 신규/변경 Document 목록 + 삭제된 source_id 목록 + 새 SyncState
```

- `SyncState`(커넥터별 마지막 동기화 커서)는 index.db 내 테이블에 저장한다.
- 삭제 전파 (P0): 커넥터는 현존 ID 목록 대조로 삭제를 보고하고, 인덱서는 해당 청크와 요약본을 제거한다.
- 새 소스(추후 회사 일정 등)는 `Connector` 구현 하나 추가로 붙는다.

## 7. 커넥터 설계

### 7.1 local_docs — 로컬 문서 요약 파이프라인 (M1)

1. 설정된 감시 폴더를 스캔, 수정시각+크기 변화로 신규/변경 감지 (`.pptx` `.xlsx` `.docx` `.pdf`)
2. markitdown으로 로컬 텍스트 추출
3. **DRM/암호화 감지 (P0)**: 변환 예외 발생 또는 추출 텍스트의 유효 문자 비율이 임계치 미만이면 DRM으로 판정
   - 폴백: 파일명·경로·수정일·크기만으로 인덱싱. 파일명을 Gemini로 해석해 짧은 추정 설명 생성. `content_indexed=False`, 검색 결과에 "🔒 내용 미인덱싱(DRM)" 배지 표시
4. 정상 추출 시: 텍스트가 임계치 미만(이미지 위주 PPT)이면 슬라이드를 이미지로 렌더해 Gemini 비전으로 설명 보완 (P1)
5. Gemini Flash로 요약+설명 Markdown 생성, PARA 분류
   - **요약은 검색 타깃으로 설계 (P1)**: 요약 프롬프트에 예상 질문 5개·핵심 키워드·고유명사(사람/프로젝트명) 섹션을 포함 → 임베딩·키워드 매칭률 향상
   - **PARA 분류 (P0)**: 사용자가 config(GUI 편집 가능)에 유지하는 **활성 Projects/Areas 닫힌 목록**에 우선 매핑. 어디에도 안 맞으면 `Resources/<주제>/`에만 LLM 자유 분류
   - **분류 안정화 (P0)**: `원본경로 → (PARA 위치, 요약파일)` 매핑을 index.db에 기록. 재요약 시 기존 위치를 프롬프트에 제시. 위치 변경 시 이전 복사본을 이동 — 중복 생성 금지
6. `summaries/<PARA>/<이름>/`에 요약 `.md` + 원본 파일 복사 저장, 인덱스 등록
7. **Archive 워크플로 (P1)**: GUI에서 프로젝트 완료 처리 → 해당 폴더를 `Archives/`로 이동하고 인덱스 매핑 자동 갱신

### 7.2 confluence / jira — 사내 서버 동기화 (M3)

- GUI에서 URL 등록 → 페이지 ID/이슈 키 파싱 → REST API로 **페이지+하위 트리** (Jira: 이슈+댓글) 수집
- **인증 3단 폴백 (P0)**: PAT(DC 7.9+) → Basic(사번/비밀번호) → 브라우저 세션 쿠키 수동 붙여넣기. 첫 등록 시 자동 진단으로 가능한 방식 판별, 쿠키 만료 시 GUI에서 갱신 안내. 자격증명은 Windows 자격 증명 관리자(keyring) 저장 — 평문 config 금지
- HTML → Markdown 변환 후 `confluence/스페이스/페이지계층/`, `jira/PROJ-123.md` 저장
- 주기 동기화는 수정시각 비교로 변경분만, 삭제 페이지는 인덱스·미러에서 제거

### 7.3 notes — 내 Markdown 폴더 (M1)

설정된 폴더의 `.md`를 그대로 인덱싱. 변환·요약 없음.

### 7.4 outlook_mail — 메일 (M2)

- pywin32 COM (전용 워커 스레드, Outlook 실행 필요 — 미실행 시 소스 비활성 + 안내)
- 설정: 폴더 목록·기간 (기본: 받은편지함+보낸편지함 1년), **제외 규칙**(폴더·발신자 패턴, 기본 빈 목록) (P1)
- **인용 체인·서명 절단 (P1)**: "-----Original Message-----", "보낸 사람:" 류 구분선 이후 절단, 서명 휴리스틱 제거 후 인덱싱
- 증분: `ReceivedTime` > 마지막 동기화 시각. 파일 미러 없음, 결과 클릭 시 EntryID로 Outlook에서 열기
- **콜드스타트 (P0)**: 초기 수만 통 인덱싱은 진행 커서를 index.db에 기록해 중단·재개 가능, GUI에 진행률 표시, 완료 전에도 인덱싱된 범위에서 검색 동작

### 7.5 outlook_cal — 일정 (M2)

- 기본 캘린더, 설정 기간(기본 과거 3개월~미래 6개월) 조회. 반복 일정은 조회 기간 내로만 전개
- 제목·시간·장소·참석자·본문 인덱싱. 날짜를 텍스트에 명시적으로 포함해 "다음 주 팀 미팅 언제?" 대응

## 8. 인덱스와 검색

**청킹**: 문서를 ~800자 단위(문단 경계 우선)로 분할. 청크에 문서 제목·날짜를 헤더로 포함.

**임베딩**: Gemini 임베딩 API, MRL 절단 768차원 (P1 — 3072차원은 저장·검색 비용 4배). 배치 호출. 임베딩 모듈은 인터페이스로 분리해 추후 로컬 bge-m3 교체 가능.

**검색 툴** (내부 함수이자 Claude에게 주는 툴):

```
search(query: str, source_filter: list[str] | None,
       date_range: (from, to) | None, sender: str | None) -> list[Hit]
```

- 구현: 벡터 상위 30 + FTS5 상위 30 → RRF 융합 → 문서당 최대 3청크 (P1 — 한 문서 독점 방지) → 상위 12
- **랭킹 조정 (P1)**: 최신성 부스트 + `Archives/` 소속 문서 감쇠 — 제외가 아닌 하향이므로 과거 자료 검색은 여전히 가능
- 구조화 필터 (P0): 인덱스에 날짜·보낸이·소스 컬럼을 두고 SQL로 필터. **일정·메일 질문("다음 주 미팅 언제?")은 임베딩이 아니라 날짜 범위 필터가 정답 경로**
- 히트는 청크가 아니라 **문서 단위로 승격**: local_docs는 요약 md 전체, 메일·일정·notes는 본문, Confluence/Jira는 미러 md — 청크는 문서를 찾는 포인터로만 사용. 문서 1건당 승격 상한 6,000자(초과 시 히트 청크 주변 섹션만 발췌)

**답변 플로우** (질문 1건, 에이전틱 루프):
1. 질문으로 `search` 1회 선실행 (fast path, 질의 임베딩은 캐시)
2. 결과 문서들 + `search` 툴을 Claude에 제공. Claude가 부족하다고 판단하면 재질의·필터 변경으로 **최대 3회 추가 검색** (복합 질문·다중 홉 대응)
3. 시스템 프롬프트: 근거 없는 내용 생성 금지, 주장마다 출처 번호, 현재 날짜 주입, **활성 Projects/Areas 목록 주입** (진행 중 업무 관련 문서 우선 판단용, P1)
4. 응답 = 답변(SSE 스트리밍) + 출처 카드(제목·소스 아이콘·날짜·DRM 배지·원본 열기)
5. 후속 질문: 세션 내 대화 이력을 Claude 컨텍스트에 포함, 검색은 매번 수행

**스키마**: `schema_version` 테이블 보유. 버전 불일치 시 재인덱싱 안내 (마이그레이션 코드 없음, §3 결정 참조). `rebuild` 명령으로 전체 재구축 — 기존 요약 md는 재사용.

## 9. 비용·보안 통제

- Gemini·Claude 모두 유료 티어 전제. API 키는 keyring 또는 `.env`(gitignore) — 문서·config 평문 금지
- 일일 API 호출 상한(설정) + 누적 사용량 카운터(P2 — v1은 로그 출력, GUI 표시는 추후)
- 상한 도달 시 요약·인덱싱만 일시정지, 검색은 유지
- 웹서버 127.0.0.1 바인딩 고정

## 10. 리스크 레지스터

| 리스크 | 확인 방법 | 폴백 |
|---|---|---|
| sqlite-vec Windows 휠 미동작 | M1 첫날 30분 스파이크 스크립트 | numpy 브루트포스 (중규모 충분) 또는 LanceDB |
| 사내 Confluence가 SSO로 Basic 인증 차단 | M3 첫날 curl 진단 | 쿠키 수동 붙여넣기 경로 (§7.2) |
| DRM 파일 비율이 높아 local_docs 가치 하락 | M1에서 감시 폴더 스캔 통계 확인 | 파일명 기반 인덱싱은 유지, 필요 시 DRM 해제 사본 폴더 운용은 사용자 판단 |
| Gemini 임베딩 속도 제한으로 콜드스타트 지연 | M2 초기 인덱싱 로그 | 배치 크기 조정, 야간 실행, 재개 가능 구조로 흡수 |
| markitdown 한글 인코딩 문제 | M1 실문서 샘플 테스트 | 인코딩 명시 재시도, 실패 시 DRM 폴백 경로 재사용 |

## 11. 테스트

- 커넥터 단위 테스트: 고정 픽스처(가짜 Confluence 응답, 샘플 pptx, DRM 흉내 파일)로 `Document` 변환 검증
- 검색 회귀: 픽스처 문서 + mock 임베딩으로 "질문→기대 문서 상위" 검증
- 골든 평가 스크립트 (P1): 실데이터 질문 세트로 상위 3위 적중률 측정, 파라미터 변경 시 회귀 확인
- LLM·임베딩 호출부는 인터페이스 분리로 mock 주입
- Outlook COM은 자동화 불가 → 수동 점검 스크립트 제공
- WSL에서 테스트 실행 가능하게 pywin32는 조건부 import, 경로는 `pathlib`

## 12. 데이터 폴더 구조

```
llmsearch-data/            # 위치는 config로 지정 (예: D:\llmsearch-data\)
├─ config.yaml             # 소스 경로, 동기화 주기, 메일 폴더/기간, 제외 규칙, 활성 Projects/Areas 목록 (키 제외)
├─ .env                    # API 키 (gitignore 대상, keyring 사용 시 생략)
├─ index.db                # SQLite (FTS5 + sqlite-vec + SyncState + PARA 매핑 + schema_version)
├─ summaries/              # PARA 구조: 요약 md + 원본 복사본
│   ├─ Projects/<프로젝트>/  # 활성 프로젝트 (사용자 관리 닫힌 목록)
│   ├─ Areas/<영역>/        # 지속 책임 영역 (사용자 관리 닫힌 목록)
│   ├─ Resources/<주제>/    # 어디에도 안 맞는 참고자료 — 여기만 LLM 자유 분류
│   └─ Archives/           # 완료 프로젝트 이동분 (검색 감쇠 적용)
├─ confluence/<스페이스>/…  # 페이지 트리 미러 (md)
├─ jira/PROJ-123.md
└─ notes/                  # 직접 작성 md (기존 폴더 등록도 가능)
```
